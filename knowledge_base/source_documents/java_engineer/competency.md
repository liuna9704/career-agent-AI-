# Java开发工程师岗位能力模型

## 岗位介绍
负责服务端业务开发、接口与数据模型设计、性能优化和线上稳定性保障。候选人需要兼顾语言基础、主流框架、数据存储、分布式架构与工程交付。

## 能力维度：Java基础
考察目标：集合框架、并发编程、JVM、异常与面向对象设计。
初级表现：能使用常用集合和线程池，理解基本语法。
中级表现：能解释HashMap、线程池参数、锁和JVM内存区域，并定位常见问题。
高级表现：能结合源码、性能数据和业务约束完成并发与JVM调优。
追问方向：HashMap扩容、volatile与synchronized、GC选择、内存泄漏排查。
优秀回答特征：原理准确，能给出项目案例、量化指标和方案权衡。
常见不足：只会背概念，无法说明适用边界。
评分标准：初级60-70，中级71-85，高级86-100。

## 能力维度：Spring Boot
考察目标：IOC、AOP、自动配置、事务、接口设计和工程组织。
初级表现：能创建基础接口并使用常用注解。
中级表现：理解Bean生命周期、事务传播和自动配置，能处理常见工程问题。
高级表现：能扩展框架、治理复杂依赖并设计可维护的服务架构。
追问方向：循环依赖、事务失效、Starter机制、异常处理和接口幂等。
优秀回答特征：说明框架选型原因、配置机制和真实故障案例。
常见不足：停留在注解使用层面。
评分标准：初级60-70，中级71-85，高级86-100。

## 能力维度：MySQL
考察目标：索引、事务、锁、执行计划、SQL优化与高可用。
初级表现：会编写SQL并使用基础索引。
中级表现：能分析执行计划、联合索引和事务隔离问题。
高级表现：能处理大表、热点写入、主从延迟和复杂性能瓶颈。
追问方向：最左匹配、覆盖索引、MVCC、死锁排查、分库分表。
优秀回答特征：以执行计划和压测数据验证优化结果。
常见不足：认为增加索引一定能提升性能。
评分标准：初级60-70，中级71-85，高级86-100。

## 能力维度：Redis
考察目标：数据结构、缓存策略、缓存一致性、分布式锁、持久化与高可用。
初级表现：会使用String、Hash、List、Set并设置过期时间。
中级表现：能解决缓存穿透、击穿、雪崩，理解Cache Aside缓存策略和数据库一致性。
高级表现：能设计高并发热点缓存，分析主从、哨兵、集群及分布式锁的正确性边界。
追问方向：延迟双删、订阅binlog、缓存一致性、Redisson看门狗、分布式锁误删与续期、热点Key治理。
优秀回答特征：能说明更新数据库与删除缓存的顺序、失败补偿和一致性取舍。
常见不足：用SETNX实现锁却忽略唯一标识、原子释放、超时和续期。
评分标准：初级60-70，中级71-85，高级86-100。

## 能力维度：分布式系统
考察目标：服务治理、一致性、消息队列、容错、限流与降级。
初级表现：理解微服务和RPC基本概念。
中级表现：能设计幂等、重试、熔断和最终一致性方案。
高级表现：能在复杂故障和容量约束下完成架构取舍与稳定性治理。
追问方向：CAP、事务消息、重复消费、雪崩、服务降级和全链路压测。
优秀回答特征：明确故障模型、一致性级别和恢复策略。
常见不足：只描述组件，不说明异常路径。
评分标准：初级60-70，中级71-85，高级86-100。

## 能力维度：工程实践
考察目标：Git、测试、日志、监控、容器化、发布与问题排查。
初级表现：能按规范提交代码并完成基本部署。
中级表现：具备单元测试、日志分析、Docker和CI/CD实践。
高级表现：能建设可观测性、灰度发布、容量规划和故障复盘体系。
追问方向：线上故障定位、指标设计、回滚、压测和代码质量保障。
优秀回答特征：完整描述发现、定位、解决、验证和复盘闭环。
常见不足：没有量化结果或只依赖人工测试。
评分标准：初级60-70，中级71-85，高级86-100。
